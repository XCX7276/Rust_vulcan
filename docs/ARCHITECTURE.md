# Архитектура Parodia

Состояние: **этап 5** — окно и Vulkan, ядро мира, простая генерация, построение моделей чанков (binary greedy meshing), отрисовка ландшафта, летающая камера, фоновая подгрузка и выгрузка мира в рабочих потоках, отсечение невидимого на видеокарте (поле зрения → Hi-Z → стороны граней) и indirect-отрисовка.

## Модули (крейты)

```
parodia-app  (запускаемая программа parodia.exe: окно, ввод, камера, стример мира)
 ├── parodia-render  — Vulkan: видеокарта, swapchain, глубина, пул геометрии, ландшафт, интерфейс
 ├── parodia-mesh    — квады чанка из блоков (binary greedy meshing)
 │    └── parodia-world
 ├── parodia-world   — координаты, блоки, чанки, шум, генератор
 ├── parodia-ui      — переводы (assets/lang) и экраны интерфейса (сейчас F3)
 └── parodia-core    — флаги окружения, журнал, счётчик FPS, пул рабочих потоков
```
Стрелка вниз = «использует». Нижние модули ничего не знают о верхних.

Модули, которые появятся позже (по этапам ТЗ):
`parodia-save` (9), `parodia-items` (9), `parodia-assets` и `parodia-anim` (10), `parodia-net` (12),
`parodia-audio`.

## Мир: данные

- Координаты блоков и чанков — `i64`; блок → чанк — сдвиг на 5 бит (верно и для отрицательных).
- Порядок ячеек в чанке: X быстрее всего, затем Z, затем Y (`index = y·1024 + z·32 + x`).
- Чанк из одного блока (воздух, сплошной камень) занимает 0 байт кучи; чанк с 2 видами блоков — 4 КБ,
  с 3–4 видами — 8 КБ, вместо 64 КБ при хранении `u16` в каждой ячейке.
- Блоки задаются в `assets/data/blocks.json`; номер блока = позиция в файле, воздух всегда 0.

## Ландшафт: от блоков до экрана

1. **Генерация** (`TerrainGenerator::generate`): чанк по зерну и координатам; чанки целиком в воздухе
   или в камне сразу однородные. По высоте берутся только чанки около поверхности.
2. **Меш** (`Mesher::mesh`): расширенный куб 34³ (чанк + по слою от 6 соседей) → столбцы непрозрачности
   по 3 осям (биты u64) → видимые грани `col & !(col >> 1)` → плоскости 32×32 по виду блока →
   жадное слияние в прямоугольники. Пустой чанк и сплошной чанк в окружении сплошных — сразу 0 квадов.
   Квады выдаются группами по сторонам (+X, −X, +Y, −Y, +Z, −Z) вместе с числом квадов каждой стороны.
3. **Квад** — 8 байт: x, y, z (по 5 бит), ширина−1, высота−1 (по 5 бит), грань (3 бита) | номер блока (16 бит).
4. **Видеопамять**: все квады в одном буфере 64 МБ (`RangeAllocator`); у каждого чанка — слот в таблице
   чанков: запись 32 байта (угол относительно точки отсчёта рендера, «живой», первый квад, число квадов
   каждой стороны по 16 бит).
5. **Отсечение** (`cull.comp`, поток на слот): чанк вне поля зрения → пропуск; закрытый горой → пропуск (Hi-Z);
   стороны, повёрнутые от камеры, → не рисуются; соседние видимые стороны сливаются в одну команду
   (не больше 3 команд на чанк). Команды пишутся в буфер, их число — в счётчик.
6. **Отрисовка**: один `vkCmdDrawIndirectCount` на проход; команда = `(квады·6, 1, первый_квад·6, слот)`;
   вершинный шейдер сам достаёт квад по `gl_VertexIndex / 6` и угол по `gl_VertexIndex % 6`
   (vertex pulling, без вершинного буфера), запись чанка — по `gl_InstanceIndex` (= слот).
7. **Точность**: камера для видеокарты всегда в начале координат; позиция = (целая часть − точка отсчёта)
   в целых числах + дробная часть в float — мир не дрожит вдали от центра.
8. **Глубина**: обратная (reverse-Z) с бесконечной дальней плоскостью: очистка 0, сравнение «больше или равно».

## Потоки

- **Главный поток**: окно, ввод, камера, стример (решения и учёт), запись команд Vulkan.
- **Рабочие потоки** (`parodia-worker-N`, по умолчанию ядра − 2, не больше 6): сведения о столбцах
  (высоты), генерация чанков, построение мешей. У каждого потока свой `Mesher` с буферами.
- Данные чанка после генерации не меняются и лежат в `Arc<Chunk>`: в задание мешинга передаются
  ссылки на чанк и 6 соседей, без копирования. Правки блоков (этап 8) будут делать копию при записи.
- Заданий «в полёте» не больше `потоки × 4`: при быстром полёте старые задания не копятся,
  а их результаты для уже выгруженных чанков просто отбрасываются (у мешей — по номеру версии).

## Стриминг мира

1. Каждый кадр стример забирает готовые результаты, при смене чанка камеры выгружает дальнее
   и при необходимости пересчитывает, что нужно, сортирует по приоритету и раздаёт задания.
2. По горизонтали: высоты столбцов — круг R+2, генерация — R+1, модели — R, выгрузка — дальше R+3.
3. По высоте: полоса поверхности столбца (по нему и 8 соседям) **и** окно ±`VRADIUS` вокруг камеры.
4. Модель строится только когда сгенерированы все 6 соседей (за пределами мира по высоте соседа не ждём).
5. Приоритет: квадрат расстояния до камеры, умноженный на 0,5 впереди по взгляду и до 1,25 позади;
   модели — на 20 % раньше генерации того же места.
6. Загрузка в видеопамять без ожидания: `upload_chunk` сразу выдаёт место в пуле и слот, данные
   копируются в начале ближайших кадров через «свою» часть промежуточного буфера (8 МБ на кадр в полёте).
   Запись чанка в таблице пишется в том же кадре — с него чанк участвует в отсечении.
7. Удалённый чанк: его запись в таблице обнуляется в начале ближайшего кадра, а место в пуле и слот
   освобождаются, когда этот кадр завершён на видеокарте.

## Кадр

1. Ждём fence слота (2 кадра в полёте: процессор готовит кадр N+1, пока видеокарта рисует N).
2. Читаем замер времени видеокарты и счётчики отсечения этого слота; освобождаем удалённые чанки.
3. Берём картинку swapchain (`vkAcquireNextImageKHR`).
4. Записываем команды:
   1. изменения таблицы чанков (удаления, новые записи) и копирование мешей (≤ 8 МБ);
   2. обнуление счётчиков → **ранний проход отсечения**: чанки в поле зрения, видимые в прошлом кадре;
   3. **проход 1**: очистка цвета и глубины → ранний список ландшафта (`vkCmdDrawIndirectCount`);
   4. **пирамида глубины** из глубины прохода 1 (уровень 0 — степень двойки не больше экрана,
      каждая точка — самая дальняя глубина своей области) → **поздний проход отсечения**: остальные чанки
      проверяются по пирамиде, открывшиеся попадают в поздний список; видимость запоминается на следующий кадр;
   5. **проход 2**: поздний список ландшафта → интерфейс F3;
   6. копия счётчиков для процессора → барьер для показа.
5. `vkQueueSubmit2` → `vkQueuePresentKHR`.

Без Hi-Z (`PARODIA_OCCLUSION_CULLING=0`) ранний проход берёт все чанки в поле зрения, а пирамида
и поздний проход пропускаются.

Swapchain пересоздаётся при смене размера окна; при свёрнутом окне кадры пропускаются.
`vkDeviceWaitIdle` вызывается только при пересоздании swapchain и при выходе.

## Порядок уничтожения

`Renderer::drop`: ждём видеокарту → интерфейс → отсечение → ландшафт → глубина → таймер → swapchain → ресурсы кадров →
распределитель памяти;
затем `GpuContext::drop`: устройство → поверхность → отладочный канал → экземпляр Vulkan.
В `App` рендер уничтожается раньше окна (порядок полей в `Running`).
