# Решения Parodia

Здесь записывается, что и почему решено, и все временные места (`TEMPORARY:` в коде).

## Принятые решения

| № | Решение | Почему |
|---|---|---|
| 1 | Свой движок: Rust + Vulkan 1.3 через `ash`, окно `winit` | полный контроль над рендером и оптимизацией; путь проверен Arivel |
| 2 | Без mesh shaders; vertex pulling + indirect draw + compute-отсечение | встроенная Vega их не поддерживает |
| 3 | Dynamic rendering + synchronization2 (Vulkan 1.3) | меньше кода, чем render pass/framebuffer, понятнее барьеры |
| 4 | 2 кадра в полёте | процессор и видеокарта работают параллельно, задержка минимальная |
| 5 | Семафор «дорисовано» — на каждую картинку swapchain, а не на кадр | иначе семафор может переиспользоваться, пока его ещё ждёт показ |
| 6 | egui — только для экрана отладки F3 | быстро и надёжно; игровой интерфейс будет свой, пиксельный |
| 7 | Версии библиотек: ash 0.38, winit 0.30, gpu-allocator 0.28, egui 0.36, egui-ash-renderer 0.13 | проверенно совместимый набор |
| 8 | Свой простой журнал (`parodia-core::logging`) вместо готового | одна зависимость меньше; пишет и в консоль, и в файл |
| 9 | Ошибки — `anyhow` | короткий код и цепочки причин в журнале |
| 10 | Тексты интерфейса — только в `assets/lang/*.json`, встраиваются в exe | в коде нет русского; переводы не теряются |
| 11 | Офлайн-сборка — через кеш Cargo (`cargo build --offline`) | `cargo vendor` скачал бы библиотеки для всех ОС (сотни МБ); при необходимости включим позже |
| 12 | Чанк хранится как «однородный» или «палитра + упакованные номера» (1/2/4/8/16 бит) | подземелье и небо — однородные чанки почти без памяти; ширина — степень двойки, номер не пересекает слово u64 |
| 13 | Реестр блоков из JSON, разбор через `serde_json::Value` без `serde`-макросов | данные отдельно от кода, на одну зависимость меньше |
| 14 | Квад = 8 байт, vertex pulling, без вершинного буфера | в 4–8 раз меньше памяти и трафика, чем вершины с float-координатами; важно для встроенной Vega |
| 15 | Один пул геометрии на все чанки + слот чанка через `firstInstance` | один набор привязок на весь ландшафт; формат вызова совпадает с indirect-отрисовкой (этап 5) |
| 16 | Позиция камеры: целая часть + дробная; камера для GPU в начале координат | точность не падает вдали от центра мира |
| 17 | Обратная бесконечная глубина (reverse-Z), D32_SFLOAT | максимальная точность глубины на больших расстояниях, нет дальней плоскости |
| 18 | Шейдеры компилируются при сборке (`build.rs` + glslc из Vulkan SDK) | ошибка в шейдере видна сразу при сборке; SPIR-V встраивается в exe |
| 19 | Комментарии в шейдерах — на английском, пояснения к ним — в `docs/ARCHITECTURE.md` | компилятор шейдеров может не принять кириллицу в исходнике |
| 20 | Меш строится только когда сгенерированы все 6 соседей | нет лишних стенок на стыках и краях; не нужно перестраивать модель при появлении соседа |
| 21 | Свой пул потоков (std: Mutex + Condvar + mpsc), без сторонних библиотек | простая и понятная очередь по приоритету; состояние на поток (свой `Mesher`) |
| 22 | Лимит заданий «в полёте» = потоки × 4 вместо отмены заданий | при быстром полёте очередь не растёт; устаревшие результаты отбрасываются по версии |
| 23 | По высоте грузится полоса поверхности + окно вокруг камеры | поверхность видна с любой высоты; под землёй не грузится небо, на горе — глубина |
| 24 | Загрузка мешей — через промежуточный буфер на каждый кадр в полёте, копирование в командах кадра | процессор не ждёт видеокарту; бюджет 8 МБ за кадр ограничивает рывки |
| 25 | «Время процессора» в F3 — без ожидания видеокарты и монитора; ожидание показывается отдельно | при VSync ожидание иначе выглядело бы как нагрузка |
| 26 | Отсечение целиком на видеокарте (compute), отрисовка через `vkCmdDrawIndirectCount` | процессор не перебирает чанки; число вызовов не зависит от числа чанков; база для LOD и теней |
| 27 | Hi-Z в два прохода (видимое в прошлом кадре → пирамида → дорисовка открывшегося) | без дыр при повороте камеры и без задержки на кадр; работает и под землёй |
| 28 | Пирамида глубины строится своим compute-шейдером с ручным минимумом, уровень 0 — степень двойки | не нужна функция видеокарты `samplerFilterMinmax`; область округляется наружу — проверка не ошибается в сторону «закрыто» |
| 29 | Квады чанка сгруппированы по 6 сторонам, отсекаются целые группы, видимые соседние группы сливаются | вершинный шейдер не тратится на грани спиной к камере (примерно половина); ≤ 3 команд на чанк |
| 30 | Запись чанка 32 байта; изменения таблицы — `vkCmdUpdateBuffer` в начале кадра | маленькие записи без промежуточного буфера; удаление вступает в силу в том же кадре |
| 31 | Если нет `vkCmdDrawIndirectCount` — рисуется весь используемый участок списка, лишние команды обнулены | игра работает и на такой видеокарте, только немного медленнее |
| 32 | Видимость нового чанка в слоте не обнуляется | худший случай — один лишний ранний вызов за кадр; поздний проход сразу исправляет |
| 33 | Hi-Z включён по умолчанию, хотя на открытой поверхности стоит ≈0,13 мс видеокарты и ничего не прячет (замер этапа 5) | обязателен по ТЗ; окупается под землёй, в пещерах и горах; < 1 % бюджета кадра при 60 FPS; выключается `PARODIA_OCCLUSION_CULLING=0` |
| 34 | LOD — дерево узлов по горизонтали (квадрат делится на 4), узлы кубические по высоте, 4 уровня 2/4/8/16 м | дальность 4 км при том же числе узлов на кольцо; уровень 0 — те же чанки |
| 35 | Дистанция дробления `k · размер узла`, k = R/2 | кольца уровней получаются одинаковыми по числу узлов; граница полных чанков совпадает с радиусом R |
| 36 | Узел LOD хранится и рисуется как обычный чанк 32³ с масштабом клетки | тот же мешер, пул, отсечение и шейдер; ноль нового кода рендера |
| 37 | Высота клетки LOD — по центру клетки; верхняя клетка — трава, следующая — земля | просто и детерминированно; на этапе 12 заменится вместе с генератором |
| 38 | Сосед узла LOD по краю — упрощённая копия соседнего узла, опущенная на одну клетку; под узлом — камень | «юбка» высотой в клетку закрывает щели между уровнями без сшивания геометрии; у узла нет дна и глубоких стенок — из-под земли он не виден висящей коробкой |
| 39 | Смена уровня — целыми группами: новое показывается и старое убирается в одном кадре, только когда новое готово целиком (`gate`/`hold`) | ни дыр, ни двойной отрисовки (мерцания) на границе |
| 40 | Импосторы перенесены на этап 12 | сейчас в мире нет деревьев и крупных объектов — рисовать импосторами нечего |
| 41 | Углы горизонтальных квадов (верх/низ) сдвигаются наружу на полпикселя **на экране** по каждой оси квада (вершинный шейдер, размер картинки — в push constants) | слитые квады стыкуются «Т-образно», и растеризация оставляет тонкие щели (до неба или до тёмной стенки под границей чанка/узла LOD); под острым углом блок занимает меньше пикселя, поэтому сдвиг считается в пикселях, а не в блоках; стены не растягиваются — иначе их край торчит над землёй вдоль ступенек |
| 42 | Время суток считается только из часа (без случайности), в `parodia-core` | одинаковая картинка при одинаковом часе; для сети время будет присылать сервер |
| 43 | Ночью прямой свет и тени — от луны; у горизонта яркость солнца и луны уходит в ноль | смена источника (и направления теней) не видна |
| 44 | Данные кадра — в одном uniform-буфере на кадр «в полёте» вместо push constants | push constants ограничены 128 байтами, а теперь нужны матрицы 4 каскадов, цвета неба и тумана |
| 45 | 4 каскада 24/64/160/400 м, карта D16 2048², кеш: дальние каскады раз в 2/4/8 кадров, не больше 2 за кадр | на Vega отрисовка теней — самая дорогая часть света; дальние каскады меняются медленно |
| 46 | Каскад — шар вокруг отрезка обзора + сдвиг центра по сетке точек карты | размер точки тени постоянный, тени не дрожат при движении и повороте камеры |
| 47 | В каскады рисуются только стороны, повёрнутые **от** света (отсечение целыми группами) | вдвое меньше геометрии теней; освещённая грань не затеняет сама себя — почти не нужен сдвиг, из-за которого тени «отъезжали» от предметов |
| 48 | AO — при построении модели (вершинный), затенённые грани не сливаются; только для полных чанков | дёшево для Vega; экранный GTAO — позже, на высоких настройках; на узлах LOD клетка 2–16 м и AO не нужен |
| 49 | AO у края чанка считает соседние чанки по рёбрам и углам воздухом | мешеру передаются только 6 соседей по граням; заметно лишь как чуть более светлый угол у границы чанка |
| 50 | Небо рисуется после ландшафта с проверкой глубины «больше или равно» на глубине 0 | шейдер неба работает только там, где ничего не нарисовано |
| 51 | Туман по высоте (аналитический интеграл) + скрытие у края дальности; цвет тумана = цвет неба по направлению | дымка вдали без лишних проходов; край мира не виден |
| 52 | Тени пиксельные: тень берётся в центре «пикселя» блока (1/16 блока) по сетке мира, без сглаживания; пиксель одинаковый во всех каскадах; размер точки карты — степень двойки, её границы вдоль Z совпадают с границами блоков | края теней — ступеньки из пикселей блока, параллельные граням, как и весь пиксельный мир; нет косой «лесенки» точек карты; тонкие тени вдали не пропадают и не прыгают на границах каскадов |
| 53 | Направление теней меняется шагами в игровую минуту (0,25° хода солнца); свет — плавно | тени не «плывут» вместе с солнцем; за шаг край сдвигается меньше пикселя блока |
| 54 | Солнце и луна — пиксельные диски 16×16, размер задаётся флагом (по умолчанию 2,5°) | пиксельный стиль; размер — будущая настройка в меню (этап 10) |
| 55 | По умолчанию солнце и луна ходят в плоскости X–Y через зенит (без наклона к Z), как в Minecraft; склонение — флаг `PARODIA_SUN_TILT` (0–60°) | свет всегда перпендикулярен оси Z: тени всех рёбер блоков ложатся вдоль X и Z — параллельно граням, без косой «лесенки» и «ряби» вдали; оси карты теней совпадают с осями мира |
| 56 | При смене направления теней перерисовываются сразу все 4 каскада | иначе каскады какое-то время показывали тени разных «шагов», и на их границах тени прыгали туда-сюда |
| 57 | Без сдвига глубины в карте теней | в карте только стороны, повёрнутые от света, — сдвиг не нужен, а он давал светлую щель у основания стен |
| 58 | В карте теней стены продлены на полблока вниз, в землю | конечный размер точек карты оставлял светлую щель у основания стен (шире всего при низкой луне); продолжение внутри сплошной земли больше нигде тени не даёт |
| 59 | Порядок по глубине для перекрывающихся граней одной плоскости: квадраты с AO чуть ближе слитых, соседние квадраты с AO — по шахматному порядку (сдвиг глубины 4·10⁻⁶) | растянутые на полпикселя грани (решение 41) перекрываются; там, где соседи затенены по-разному, победитель зависел от порядка отрисовки — край полосы AO у стен был «рваным» и мерцал |
| 60 | Оси карты теней — по рёбрам блоков: x карты ⊥ Z мира, y карты ⊥ X мира, обе ⊥ лучам (косая проекция вдоль лучей); прежние квадратные оси — `PARODIA_SHADOW_GRID=sun` / клавиша G | идея пользователя (рисунок с тенью куба): у квадратной карты при склонении солнца рёбра вдоль X и Z идут наискосок к её точкам — край тени «зубцами»; с косыми осями они всегда идут по строкам и столбцам карты. Цена: при низком солнце точка карты на земле вытянута сильнее; размер карты тот же |
